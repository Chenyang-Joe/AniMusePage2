按「方向」分组。点 预览 在卡片内加载实页（缩略 28%），点 打开 在新标签看真实效果。
看完告诉我走哪个方向 / 或者「A 的骨架 + C 的交互」这种组合也行。

要决定的不用一次全定，先挑「骨架」和「交互深度」两个就够我开工
① 排版骨架居中窄栏（Nerfies 经典） vs. 宽栏分 section vs. 左侧 sticky 目录导航（适合你「介绍要详细 + 分 stage」的诉求）
② 视觉温度纯白 + 黑字 + 蓝链接（最学术） vs. 米白/浅灰底 + 细边框卡片 vs. 深色 hero + 白色正文
③ 交互深度只有视频/图 vs. 视频 + 少量 3D viewer vs. 大量 three.js 组件（我们要的 blob↔mesh slider、editing slider 属于这档）
④ 首屏大 teaser 图 vs. 自动播放的 muted 视频 vs. 直接一个可交互 3D

方向 A：经典 Nerfies 学术模板 safe / 最“传统学术”

居中窄栏、Bulma 排版、作者行 + 一排 pill 按钮 + 大 teaser 视频 + Abstract + Method + Results + BibTeX。 审稿人最熟悉，绝对不会显得“过于艺术”。缺点：分 stage 展示的空间有限，容易显得平。

方向 B：现代极简排版流 你给的三个例子基本都在这一档

还是学术味，但脱掉 Bulma：自定义 CSS / Tailwind，宽一点的栏、明确的 section 分隔、顶部 sticky 导航（Abstract / Method / Results）。 最贴合你「不要艺术、但要分段、要能塞很多内容」的诉求。

RigMo你给的例子直接相关

方向 C：强交互 / 3D-first 我们那两个 slider 组件的技术参照

页面里嵌真正的 three.js / model-viewer 画布，读者能转、能拖 slider。 这是我们「blob ↔ mesh slider」和「editing slider」要落地的形态。风险是加载慢——所以这些页里我重点看的是它们怎么懒加载。
